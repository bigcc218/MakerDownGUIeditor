# MDGE 项目文件格式 v1.1

`.mdge` 是 MDGE Studio 的原生项目容器。它是一个小端序二进制格式，设计目标是快速读取、可靠校验、对未来的记录类型保持兼容，同时不依赖 ZIP、JSON 或数据库运行时。

当前离线实现对应主版本 `1`、次版本 `1`；仓库内 `samples/Welcome.mdge` 是 1.0 版本保存的存量文件，读取端仍可正常打开。

## 总体结构

```text
+---------------------------+
| 32 字节固定文件头           |
+---------------------------+
| 变长记录流（body）          |
+---------------------------+
| 4 字节结束标记 "ENDG"      |
+---------------------------+
```

文件的总长度必须恰好等于：

```text
32 + body_size + 4
```

读取端会严格验证文件签名、版本、头部长度、声明大小、CRC32 与结束标记。

## 文件头

所有整数都使用小端序。

| 偏移 | 类型 | 字段 | 说明 |
| --- | --- | --- | --- |
| 0 | `char[4]` | magic | 固定为 `MDGE` |
| 4 | `uint16` | version_major | 当前为 `1` |
| 6 | `uint16` | version_minor | 当前为 `1` |
| 8 | `uint32` | header_size | 当前为 `32` |
| 12 | `uint32` | flags | bit 0 表示 UTF-8 文本；当前写 `1` |
| 16 | `uint64` | body_size | 记录流字节数，最大 64 MiB |
| 24 | `uint32` | checksum | 记录流的 CRC32 |
| 28 | `uint32` | reserved | 必须写 0 |

版本策略：读取端拒绝不同的 `version_major`；同一主版本下接受不同 `version_minor`，以便未来增加记录或可选字段。版本 1.1 新增了任务清单内容块类型（10、11），版本 1.0 的项目仍然可以读取。

## 基本编码

### 字符串

所有文本字段使用一个 `string32`：

```text
uint32 byte_length
uint8  utf8_bytes[byte_length]
```

文本必须以 UTF-8 编码，不允许未配对的 UTF-16 代理项或过长 UTF-8 编码。长度是字节数，而不是字符数。

### 记录

每条记录由 8 字节头和 payload 组成：

```text
uint8  tag
uint8  reserved      固定为 0
uint16 version       当前为 1
uint32 payload_size  本记录 payload 字节数
uint8  payload[payload_size]
```

读取端会跳过不认识的 tag，这允许在后续次版本中追加可选记录。`END` 记录必须是记录流的最后一条，其 payload 必须为空，之后不能再有字节。

## 记录类型

| tag | 名称 | payload |
| --- | --- | --- |
| `0x01` | TITLE | 一个 `string32` |
| `0x02` | AUTHOR | 一个 `string32` |
| `0x03` | ICON_PATH | 一个 `string32`，按原样保存 |
| `0x05` | CREATED | `uint64` Unix 秒（UTC） |
| `0x06` | MODIFIED | `uint64` Unix 秒（UTC） |
| `0x07` | APP | 一个 `string32`，写入 `MDGE Studio` |
| `0x10` | BLOCK | 内容块，按文档顺序排列 |
| `0x7F` | END | 空 payload，记录流结束 |

示例项目通常包含六条元数据记录、若干 `0x10` 内容块记录，以及最后一条 `0x7F`。

未写标题时读取端使用“未命名文档”；如果项目没有任何内容块，界面打开后会补一个空白正文块。

## 内容块 payload

```text
uint8    type            0..11，见下表
uint8    reserved        0
uint16   reserved        0
uint32   block_flags     保留，当前为 0
string32 text            正文文字
string32 image_path      图片路径，图片块使用
string32 caption         图片替代文字/说明
string32 language        代码语言标识
uint32   span_count
Span     spans[span_count]
```

块类型：

| 值 | 类型 |
| --- | --- |
| 0 | 正文 |
| 1 | 一级标题 |
| 2 | 二级标题 |
| 3 | 三级标题 |
| 4 | 项目符号 |
| 5 | 编号列表 |
| 6 | 引用 |
| 7 | 代码 |
| 8 | 图片 |
| 9 | 分隔线 |
| 10 | 未完成任务项（GitHub 任务清单） |
| 11 | 已完成任务项（GitHub 任务清单） |

### 行内样式 span

`text` 是 UTF-16 文本写入 UTF-8 后的结果。样式范围以 UTF-16 code unit 计数；每个 span 不会与另一个 span 重叠。

```text
uint32   start
uint32   length
uint8    flags
uint8    reserved[3]     全为 0
string32 href            链接地址；无链接时为空串
```

`flags` 位：

| 位 | 值 | 含义 |
| --- | --- | --- |
| 0 | `0x01` | 粗体 |
| 1 | `0x02` | 斜体 |
| 2 | `0x04` | 行内代码 |
| 3 | `0x08` | 链接；此时 `href` 必须非空 |

没有 span 覆盖的字符是普通文字。读取端会验证 `start + length` 不越界，并验证 flags 只使用已定义的位。链接 span 的 href 会被收集为链接运行区间。

## CRC32

`checksum` 使用标准 CRC-32（IEEE 802.3，反射多项式 `0xEDB88320`），初值为 `0xFFFFFFFF`，最终结果再与 `0xFFFFFFFF` 异或。校验范围是完整的 body 字节流，不包含文件头和尾标记。

标准测试：

```text
CRC32("123456789") = 0xCBF43926
```

## 结束标记

文件最后四个字节固定为：

```text
45 4E 44 47    ASCII "ENDG"
```

读取端在检查记录流之前先验证 CRC 与结束标记。

## 限制

当前 v1 实现的读取限制：

- 文件最大 64 MiB。
- 记录数量最多 200000 条。
- 单个内容块的样式 span 最多 2000000 个。
- 未知记录会被跳过，不参与显示。
- 未知的主版本会被拒绝，未知的次版本会被接受。

保存端会拒绝超大型文档和无法转换为 UTF-8 的文本。

## 图标路径语义

`ICON_PATH` 是原始路径文本，不强制存储为绝对或相对路径：

- 绝对路径：直接访问该文件。
- 相对路径：读取端依次在项目目录、当前工作目录、可执行文件目录中查找，选择第一个存在的文件。
- 文件不存在时项目仍可正常打开；界面显示缺失状态和解析后的完整路径。

同样的路径解析规则也用于图片块的 `image_path`。

## 保存策略

保存时分两步执行：

1. 将完整文件写入目标目录中的唯一临时文件。
2. 使用 Windows 的原子同卷替换操作覆盖目标。

因此保存中途失败不会留下半个 `.mdge` 文件。

## 与 Markdown 源码的关系

`.mdge` 以内容块（BLOCK 记录）为存储主体，不单独保存一份原始 Markdown 文本。界面的源码面板会把编辑中的 Markdown 按支持的子集解析成内容块；“导出 MD”在没有继续修改画布的情况下使用当前源码文本，否则从内容块重新生成。

因此，对于内容块模型不支持的结构（例如表格、嵌套列表和 HTML 块），如果之后在画布中编辑再保存，重新生成的 Markdown 可能被规范化。需要无损保留这类结构时，应先导出 `.md`，或仅使用可视化编辑器支持的结构。

GitHub 任务清单以两个独立的内容块类型保存（10 表示未完成，11 表示已完成），文字仍然位于 `text` 字段，因此可以正常编辑并导出为 `- [ ]` / `- [x]`。

## 兼容性建议

- 写入端不得改变已有 tag 的 payload 含义。
- 读取端必须跳过未知 tag，并在遇到未知 flag 位时按规范决定拒绝或忽略。
- 新增字段时优先新增记录类型，或者在次版本中对已有 payload 末尾追加字段。
- `END` 必须保持为最后一条记录。
